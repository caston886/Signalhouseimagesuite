# Signal House Imaging Suite

A single Avalonia (.NET 8, C#) desktop application bundling three editing
modes in one window — **Passport Photo Editor**, **JPEG Enhancer**, and **RAW
Enhancer** — sharing one color-adjustment engine, one canvas, one undo
history, and one universal template/preset system.

## Important: this was built without a compiler in the loop

This project was written in an environment with no .NET SDK and no network
access to NuGet, so none of it has been compiled or run yet. Every file is a
complete, real implementation (no stubs, no `TODO`s standing in for logic) —
but "hasn't been build-checked" is a real risk on a project this size.
Expect a handful of small compile errors on your first `dotnet build`
(usually a slightly-off API name against whatever exact package version
NuGet resolves), not structural problems. If you hit one, the fix is almost
always local to one line — feel free to paste the error back for a fix.

Two pieces are external dependencies this project intentionally does not
(and, from this sandbox, could not) include:

### 1. Native LibRaw binary (required for the RAW editor)

`SignalHouse.Core/Imaging/RawDecoding/LibRawNative.cs` P/Invokes into
LibRaw's small, stable "simple API" (`libraw_init`, `libraw_open_file`,
`libraw_unpack`, `libraw_dcraw_process`, `libraw_dcraw_make_mem_image`,
`libraw_close`). That binds against a **native** `libraw` shared library
(`libraw.dll` / `liblibraw.so` / `liblibraw.dylib`) that is not bundled here.
Add it one of two ways:

- Search NuGet for a "LibRaw" bindings/native package and add it to
  `SignalHouse.App.csproj` (several community packages ship prebuilt
  binaries for win-x64/linux-x64/osx-x64 or osx-arm64) -- confirm the exact
  package name/version yourself, since this workspace couldn't reach NuGet
  to verify one.
- Or build LibRaw yourself from https://www.libraw.org and copy the
  resulting shared library into `SignalHouse.App`'s output directory (next
  to the `.exe`/executable).

Everything else in the RAW editor (Auto/Manual exposure and white balance,
color balance, clarity, templates, undo, canvas controls) is fully
self-contained and needs nothing external.

### 2. Optional ONNX models (automatic face detection / background segmentation)

The Passport editor's **default** background removal is chroma-key
(`ChromaKeyBackgroundRemover.cs`) -- fully self-contained, no model file, no
network, works out of the box for a studio green/blue/solid backdrop.

Two *optional* extras need a model file this project doesn't ship, because
downloading one requires network access this sandbox didn't have:

- **Automatic segmentation for arbitrary backgrounds**
  (`OnnxBackgroundRemover.cs`): drop a portrait-matting ONNX model (MODNet or
  U2Net-portrait both publish ONNX exports) at
  `Models/portrait_matting.onnx` next to the executable, and check the
  "Use automatic segmentation" box in the Passport editor.
- **Auto-center crop on detected face** (`OnnxFaceDetector.cs`): drop a
  lightweight face-detector ONNX model (e.g.
  Ultra-Light-Fast-Generic-Face-Detector) at `Models/face_detector.onnx`.

Neither file is required to use the app -- both features degrade gracefully
to a clear status message telling you to frame the crop manually if the
model file isn't present. If the specific model you pick uses different
input/output tensor names or sizes than the constants at the top of those
two files, adjust the constants to match (comments there point at exactly
what to check).

If you don't want the ONNX dependency at all, delete the
`Microsoft.ML.OnnxRuntime` package reference from `SignalHouse.Core.csproj`
and remove `OnnxBackgroundRemover.cs`/`OnnxFaceDetector.cs` -- nothing else
depends on them.

## Building

Requires the [.NET 8 SDK](https://dotnet.microsoft.com/download).

```bash
./setup.sh      # macOS/Linux -- creates the .sln via `dotnet new sln` and restores packages
# or
.\setup.ps1     # Windows PowerShell

dotnet build
dotnet run --project src/SignalHouse.App
```

(The `.sln` is generated by the setup script rather than hand-written, so
there's no risk of a malformed solution file -- it's the same thing
`dotnet new sln && dotnet sln add ...` would produce if you typed it
yourself.)

## Architecture

```
src/
  SignalHouse.Core/         Pure logic, no UI framework dependency
    Models/                 EditState (the shared "recipe"), EditPreset, PassportSizePreset
    Presets/                PresetStore -- shared JSON template storage
    History/                EditHistory -- undo/redo over EditState snapshots
    Utilities/               ColorMatrixMath, BlackBodyRadiator
    Imaging/
      ColorAdjustmentEngine.cs   Exposure/contrast/saturation/WB/color-balance -> one SKColorFilter
      ClarityFilter.cs           Local contrast, as an SKImageFilter graph
      AutoAdjustmentEstimator.cs Gray-world auto white balance + auto exposure (RAW editor's Auto mode)
      ImageDocument.cs           Open image: full-res + preview + current EditState
      ChromaKeyBackgroundRemover.cs   Studio-backdrop removal (no external deps)
      OnnxBackgroundRemover.cs / OnnxFaceDetector.cs   Optional, model-file-based (see above)
      RawDecoding/
        LibRawNative.cs / LibRawDecoder.cs   RAW pixel decode (needs native LibRaw, see above)
        RawImageConverter.cs                 RAW16 -> SKBitmap for the shared pipeline

  SignalHouse.App/          Avalonia UI (MVVM, CommunityToolkit.Mvvm)
    Controls/ImageCanvas.cs       Shared canvas: direct-Skia draw, pan/zoom/rotate, Tab-to-commit
    ViewModels/
      EditorViewModelBase.cs      Shared sliders, undo/redo, templates -- Passport/JPEG/RAW all derive from this
      JpegEditorViewModel.cs / RawEditorViewModel.cs / PassportEditorViewModel.cs
    Views/                       One View per editor + the shared ColorAdjustmentPanel
    Services/FilePickerService.cs   Open/save dialogs
```

### Why templates work across editors

Every editor's sliders write into the same `EditState` shape
(`SignalHouse.Core.Models.EditState`). `PresetStore` saves/loads that shape
as plain JSON in one shared folder
(`%AppData%/SignalHouseImagingSuite/Presets` on Windows, the equivalent
`ApplicationData` folder elsewhere). Saving a template in the JPEG editor and
opening the RAW editor shows the exact same template in its list, because
they're reading the same folder.

### Why the canvas stays smooth at 60Hz

Every slider (exposure, contrast, saturation, white balance, color balance,
clarity) is collapsed into **one** Skia color matrix plus (if Clarity is
non-zero) one blur+arithmetic filter graph, applied as a single
`SKPaint.ImageFilter` in one `DrawBitmap` call, drawn directly against the
render surface via Avalonia's custom-draw-operation + Skia-lease extension
point (`ImageCanvas.cs`) -- no intermediate CPU bitmap re-render per frame.
Editing also happens against a resolution-capped preview bitmap (2048px long
edge); full resolution is only touched once, on export.

### Canvas controls

- Left-click + drag: pan
- Scroll wheel: zoom
- Right-click + drag: free rotate
- Tab (while the canvas has focus): commits the current edit into undo
  history (`EditorViewModelBase.CommitEditCommand`)
